OpenUptime 支持的全部功能

监控

  • HTTP / HTTPS 检测
  • TCP 端口、DNS、PostgreSQL、MySQL、Redis
  • 心跳监控，适用于定时任务和后台进程
  • 关键词出现或缺失、预期状态码、自定义方法与请求头
  • 响应过慢阈值告警
  • 最短每分钟检测一次，可设置连续失败阈值
  • 暂停与恢复，支持 JSON 导入导出

故障事件

  • 故障自动创建、自动恢复
  • 可手动创建故障并发布进展，从排查中到已恢复
  • 确认故障，并记录处理人
  • 计划维护窗口，期间不发告警
  • 发送失败的告警会自动重试，并保留完整告警日志

告警渠道

  • Slack、飞书、Telegram、PagerDuty、邮件、Webhook
  • 每个监控项可单独选择告警渠道

状态页

  • 分组组件，90 天历史
  • 故障时间线与邮件订阅
  • 浅色、深色或自动主题，可选显示响应时间
  • RSS 订阅、SVG 状态徽章、可嵌入的状态摘要
  • 页眉可选添加指向自己网站的链接

自动化

  • 应用能做的，REST API 都能做
  • API 密钥，可用于脚本、Terraform 和 CI
  • MCP 服务，OAuth 授权，可限定到工作区或项目

团队与账号

  • 工作区与项目，含所有者、管理员、成员角色
  • 邮件邀请、GitHub 登录、两步验证
  • 中英文界面，账号数据导出
  • 可自托管于 Cloudflare Workers 与 Postgres，MIT 许可
MCP

让 AI Agent 替你管监控

OpenUptime 自带 MCP 服务。接入 Claude、Cursor 或任意 MCP 客户端，用自然语言就能操作。

1

接入客户端

在支持远程服务的 MCP 客户端里，添加你的 OpenUptime 地址加上 /api/mcp。

2

用 OAuth 授权

登录后选择 Agent 能访问的范围：所有工作区、选定的工作区，或只有选定的项目。可随时撤销。

3

直接提需求

创建监控、暂停、立即检测、创建和更新事件。在你允许的范围内，Agent 还能创建项目和工作区。

痛点

现有方案，总要你让步一点

多数团队的要求并不高：告警靠谱、状态页拿得出手、不被厂商绑定。

$ / mo

监控的账单涨得比业务还快

SaaS 监控按监控项、检测频率、席位和状态页分别计费。服务一多，监控本身就成了一笔不小的开销。

1 box

监控和服务一起挂

自建监控常和被监控的服务跑在同一套设施上，机器或网络一出问题，告警也跟着哑火。

no API

想自动化，却没有 API

每上线一个新服务，就得去后台手动配一遍。没有完整的 API，Terraform 和 CI 都接不进来。

核心能力

监控、告警、状态页，一个项目全搞定

开源，MIT 许可。可以部署在 Cloudflare，也可以用一个 Docker 容器运行。
